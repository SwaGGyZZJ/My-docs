# CRC32 IEEE：A / D / F 最终 patch 同窗复测（2026-10-13）

这次**没有重新运行优化智能体**。将历史 A1–A3、D1–D3 与新 F1–F3 的九份正式有效最终 patch，在 920C 上与**同一份未优化基线**重新构建、做正确性检查，然后在同一个低负载窗口测试。每个对象在 CPU0 / NUMA0 上取得 7 次交错原始吞吐量；性能单位均为 MB/s。

口径：每次优化的性能提升 = `该最终 patch 的 7 次吞吐量均值 / 共同未优化基线的 7 次吞吐量均值 − 1`。共同基线 7 次均值为 **17,750.602857 MB/s**，原值为 `17738.78, 17751.45, 17737.16, 17794.33, 17761.32, 17748.29, 17722.89`。组别性能均值是三次独立优化的提升率均值；方差是这三次提升率的**样本方差**（分母 `n−1`，单位 pp²），不是单次 7 个测速值的方差。Token、耗时和优化迭代次数仍来自原优化 session；本次复测不重新消耗模型 Token。

F 的平均提升比 D 高 **2.9393 pp**，但非缓存 Token 中位数多 **90,973**；D 比 A 的平均提升高 **3.0319 pp**，且非缓存 Token 中位数少 **137,553**。F 比 A 的平均提升高 **5.9712 pp**，非缓存 Token 中位数少 **46,580**。从这九个最终 patch 的同窗性能看，F 的均值最高、D 的非缓存 Token 最少；但每组只有三次独立优化，组内波动较大，不能把这些描述性差异说成稳定或统计显著的胜出。

**因果边界：**A / D 的优化过程发生在较早实验，F 的优化发生在 2026-10-13；本次统一了最终 patch 的*测量时间与基线*，没有统一三组的*优化生成时间*。因此这份报告不能单独证明 Kernel Wiki 对 F 产生因果收益。F 第 2 次的提升（+33.87%）也低于同序号 A2（+55.29%）和 D2（+37.90%），并非逐次全面占优。
