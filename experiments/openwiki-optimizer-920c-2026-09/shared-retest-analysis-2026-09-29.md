# 920C 五算子正式 patch 复测：均值、方差与 Token 中位数

数据截至 2026-09-29。59 个正式有效 patch 在 920C 分算子串行完成共同环境复测，均通过正确性门禁；GF r3C 没有正式可重放 patch，不把历史 invalid 当作第 60 格。五个算子的未优化源码各有一条共同基线；每个基线和 patch 都有 7 次轮换交错原始性能值，CPU0/NUMA0 绑定。GF/CRC 的吞吐量单位是 MB/s，DFT 是 Mflops，libm/TLFloat 是 Mops/s；下表统一换算为相对**同算子未优化基线**的提升百分比，不跨算子比较绝对吞吐量。

## 同组多次运行为何性能和 Token 差得多

r1–r3 是**三次独立的完整优化运行**，每次最多三轮候选迭代；每个最终 patch 又单独测 7 次。Token 消耗在优化探索阶段，七次复测只测性能。DFT A 是可审计的例子：

| DFT A | 本次最终 patch 提升 % | 原优化非缓存 Token | 缓存读取 Token | 模型 step-finish | bash 调用 | 源码 grep 次数 / 输出字节 | 原优化耗时 min |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| r1 | 22.98 | 505,256 | 51,467,264 | 256 | 197 | 46 / 21,566 | 112.28 |
| r2 | 29.90 | 333,926 | 26,305,216 | 198 | 143 | 28 / 11,806 | 47.09 |
| r3 | 9.92 | 924,467 | 88,897,920 | 377 | 273 | 49 / 50,238 | 102.43 |

r3 相对 r2 的非缓存 Token 为 2.77 倍，模型步骤为 1.90 倍，bash 调用为 1.91 倍，源码 grep 输出为 4.26 倍。其最终补丁只保留了第一轮的 ADVSIMD `reverse()` 单指令 `EXT` 改写；第二轮 twiddle 常量提升和第三轮 butterfly 尾链并行化候选测得持平而撤回。r2 则在同类 `reverse()` 改写后，继续完成 FCMLA 复数乘法及内联路径，形成不同的最终 patch。由 trace 的调用/检索量与优化报告可确认：同为“3 轮”并不意味着等量的探索、测试、调试和最终改动。**不能仅凭相关性把 Token 增量精确归因于某一条 grep 或 OpenWiki**；r3 的大量实验性 harness、候选失败与复核是可见的额外工作。缓存读取是逐次模型调用的累加命中量，不是唯一文档大小，也不是 OpenWiki 阅读次数。

这次复测的 7 次值在 CPU0/NUMA0 低负载窗口轮换交错；DFT A r1/r2/r3 的**七次配对提升样本方差**分别为 0.49、0.30、4.34 pp²，而三轮最终 patch 提升的组间方差是 102.99 pp²。因此结果差异主要体现在不同最终补丁，而非把同一补丁的七次测量抖动误记为三次独立优化的差异。不过这里只能说复测环境控制了已记录的 CPU/NUMA 与负载条件，不能声称完全消除所有硬件噪声或证明因果。

## libm、TLFloat 的收益边界

libm 场景只测 `Sleef_sin_u35`、`Sleef_cos_u35` 的几何平均吞吐，不覆盖库内其他数学函数。可复核的 B-r1 patch/优化报告显示，改动集中在 `src/arch/helperpurec_scalar.h` 的绝对值辅助函数与 `src/libm/sleefsimddp.c` 的 `xsin`/`xcos` 标量 fast path；它改善了部分实测标量路径，但原有 Cody–Waite 范围缩减、多项式和边界语义仍在，进一步改写的收益有限且有错误/性能退化风险。正式复测的 libm A 均值 8.46%，B/C/D 为 3.52%/5.79%/4.41%，均低于 A。B 的非缓存 Token 中位数 403,229，确比 A 少 6.64%，但总 Token 多 9.76%，不能说 libm 完全无 Token 优势，也不能说有性能/Token 双赢。

TLFloat 场景是 8 个操作（加、乘、除、double 转换、比较、FMA、平方根、rint）的几何平均，每项相对加速以八次方根进入总分。C-r2 的真实 patch 在 `src/include/tlfloat/tlfloat.hpp` 为 IEEE binary128 的比较、`rint` 与 double 转换做按位 fast path；优化报告记载比较约 2.27×、rint 约 1.69×、转换约 1.34×，而加/乘/除/FMA/平方根大致不变。因此局部巨大收益会被 8 项几何平均稀释，且三次独立 C patch 的复测提升分别为 16.04%、22.79%、3.24%，组间方差 98.66 pp²。C 组均值仍比 A 高 8.39 pp，但总 Token 与非缓存 Token 中位数分别高 33.55% 与 10.88%；D 组均值比 A 高 2.33 pp，非缓存 Token 低 2.10%，但总 Token 高 69.17%。所以“TLFloat 没有明显性能提升、没有任何 Token 优势”也不符合复测数据；较准确的判断是收益依赖于找到特定 fast path，且未形成稳定的总 Token 优势。

上述机制解释有两层证据边界：函数与代码路径来自正式 patch/优化报告，数值来自本次复测与原 session 计数；“为什么 OpenWiki 没有带来双赢”仍是对小样本实验的解释性推断，不能把这些相关结果当成 Wiki 的因果效应。

patch/工作负载证据：920B 归档 `920c-libm-sin-cos-dp-complete-20260923.tar.zst` 中的 `runs/formal/libm_sin_cos_dp/r1/B/git/committed.patch.zst`、`optimization-report.md.zst`；920C `retest-inputs/20260928/runs/formal/tlfloat_quad_arithmetic/r2/C/git/committed.patch.zst`、`optimization-report.md.zst`；920C `harness/run_formal_libm_sin_cos_dp.py` 与 `harness/run_formal_tlfloat_quad_arithmetic.py` 的正式 benchmark 定义。
